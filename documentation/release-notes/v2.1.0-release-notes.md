## What's in v2.1.0

v2.1.0 is an accessibility, locale-correctness, and UX-quality release. It fixes three regressions that degraded the experience for assistive-technology users and non-English speakers (Epic 75), and restructures the Forced Picks accordion panel to reduce cognitive load and scroll depth for all users (Epic 76).

---

### Forced Hero Team text now renders correctly in all languages

The Forced Hero Team feature (introduced in v2.0.0) was displaying raw key strings — for example `newGame.forcedPicks.forcedTeam.label` — instead of translated text in every locale. Root cause: the five `forcedTeam.*` locale keys were added only to the `.mjs` locale working copies and were never propagated to the `.ts` runtime catalog files that the browser actually imports. All five keys (`label`, `placeholder`, `active`, `clear`, `unavailable`) have been added to every `.ts` locale file (`en.ts`, `fr.ts`, `de.ts`, `ja.ts`, `ko.ts`, `es.ts`). The Forced Team panel now renders correctly in all supported languages.

---

### Locale selector aria-label fixed

The locale language `<select>` element was announcing the raw string `header.locale!.groupLabel` to screen readers instead of the resolved locale text. A stray TypeScript non-null assertion operator (`!`) had been accidentally embedded inside a string literal key path in `App.svelte`. The key path has been corrected to `header.locale.groupLabel`, restoring a meaningful accessible label on the control in every locale (WCAG SC 4.1.2).

---

### Skip-to-main-content link added

A visually-hidden **Skip to main content** link is now the first element reached by the Tab key from the top of the page. The link becomes visible when it receives keyboard focus, and activating it moves focus directly to the main content landmark. The link is not visible to pointer (mouse/touch) users when it does not have focus. This satisfies WCAG SC 2.4.1 (Bypass Blocks) and reduces the keyboard overhead for screen-reader and switch-access users navigating past the persistent header controls.

---

### Locale file sync test

A new automated test (`test/epic75-locale-sync-a11y.test.mjs`) verifies that every locale's `.mjs` and `.ts` catalog files carry an identical set of keys. This guards against the category of regression introduced by v2.0.0, where keys added to one format were silently absent from the other.

## Forced Picks panel restructured (Epic 76)

The Forced Picks accordion panel in the New Game tab has been reorganised to reduce cognitive load and scroll depth following five targeted structural changes.

### Duplicate heading removed

The "Forced picks" H3 heading that previously appeared inside the accordion body has been removed. The accordion toggle label already serves as the visible section heading; the H3 was redundant and added unnecessary visual weight when the panel was open.

### Consistent card-type picker layout

All five card-type picker controls (Scheme, Mastermind, Heroes, Villains, Henchmen) now share a single consistent button layout via the `.forced-pick-picker-row` CSS class. Previously the Scheme picker used a horizontal button pair while every other picker used a vertical stack, creating an inconsistent and visually confusing control group.

### Visual divider between card-picks and session settings

A `.forced-picks-section-divider` horizontal rule now separates the five card-type picker controls (the "card-picks group") from the session-settings controls (Preferred Expansion, Forced Team) below it. The divider is visible in both light and dark themes at all supported viewport widths.

### Active constraints summary moved outside the accordion

The "Active constraints" summary block (`[data-active-constraints]`) has been moved from inside the accordion body to a persistent position immediately above the Generate Setup button, outside the accordion. It is now visible whether the accordion is open or collapsed, giving users a constant overview of their active forced-pick selections without requiring them to open the panel.

### Two-column grid for card-type pickers at ≥480px

On viewports 480px wide and above, the five card-type picker controls are arranged in a responsive two-column grid via the `.forced-picks-pickers-grid` CSS class. On viewports narrower than 480px the single-column layout is preserved. The change halves the scroll depth required to traverse the card-picks group on phone-sized devices.

## UI Layout and Navigation Polish (Epic 78)

Four independent layout friction points identified in the 2026-05-02 UX review have been resolved across the History, New Game, Browse, and Collection tabs.

### History grouping row is now horizontally scrollable

The six History grouping buttons (Mastermind, Scheme, Heroes, Villains, Player Mode, Epic Mastermind) are now arranged in a horizontally-scrollable single-line pill row using `overflow-x: auto`. Previously the row could wrap to a second line at common viewport widths. All six buttons now remain on one line at any viewport width, including 320 px and 390 px; the row scrolls horizontally when the buttons overflow their container. Active/selected button styling is preserved. New CSS rules: `.button-row-scroll` and `.button-row-scroll > *` in `app-shell.css`.

### New Game status summary condensed to a single line

The three separate status cards that previously appeared in the New Game tab — "Selected mode", "Owned sets", and "Last persisted mode" — have been collapsed into a single compact `[data-new-game-status-summary]` inline element showing all three values on one line (e.g. Standard Solo · 5 sets · Last: Standard Solo). The combined element occupies no more than 80 px of vertical height at a 664 px viewport height while conveying the same information. No data has been removed.

### Browse welcome area reduced to two primary CTAs

The Browse tab hero area previously contained four near-equal-weight action buttons. It now contains exactly two buttons with distinct visual treatment: **Generate a Game** (primary) and **Manage Collection** (secondary). "Replay Walkthrough" has been relocated into the existing "Start here" help disclosure (`data-help-walkthrough-action`). "About this project" has been moved to a new `[data-browse-footer]` area at the bottom of the Browse tab with a `.button-link` style where it remains always visible. No content has been permanently removed. New CSS rules: `.browse-footer` and `.button-link` in `app-shell.css`.

### "Reset All Selections" moved to the bottom of the Sets list

The "Reset All Selections" button in the Collection tab has been moved from immediately below the "My Collection" heading to a new `[data-collection-reset-section]` positioned below all set entries in the Sets view. A brief consequence reminder text ("This clears all owned set selections." or equivalent) is rendered adjacent to the button. The existing confirmation dialog before any selections are cleared is unchanged. The `collection.resetSelections.consequence` locale key has been added to all six locale files (`en.ts`, `fr.ts`, `de.ts`, `ja.ts`, `ko.ts`, `es.ts` and their `.mjs` counterparts).

## Active Expansions layout aligned with Forced Picks (Epic 80)

### Pattern alignment

The **Active Expansions** section on the New Game tab now uses the native `<details>` / `<summary>` collapsible pattern, matching the Forced Picks section. Previously the section used a bespoke layout built with a manual `<button data-action="toggle-active-filter-panel">` element, a `$state(false)` reactive variable (`activeExpansionsPanelOpen`), and a Svelte `{#if}` block to hide and show the panel body. All three bespoke elements have been removed; the `<details>` element handles expand/collapse natively. The `data-active-filter-panel` attribute is preserved on the outer `<details>` element so existing Playwright locators continue to work without modification.

### Section reordered below Forced Picks

The Active Expansions section has been moved in DOM order to appear immediately after the Forced Picks `<details>` panel. Previously it appeared at the top of the New Game tab configuration area, above all other controls. It now renders in the logical position that matches its role: a secondary expansion filter positioned after the primary forced-pick configuration.
