## What's in v2.1.1

v2.1.1 is a code-quality release with no user-facing behavior changes. It resolves all SonarCloud-reported issues (99 issues in Epic 93, then 18 more in Epic 96) covering cognitive complexity reductions, unsafe stringification fixes, redundant type assertion removal, and parameter-count reductions. It reduces test duplication across 15 test files by extracting shared helpers (Epic 94), significantly expands unit test coverage from 63.3% to ≥ 80% SonarCloud overall coverage (Epics 95 and 97), and refactors ten oversized source files into focused single-responsibility modules, each with a co-located test file (latest commit).

---

### Critical: cognitive complexity reductions

Cognitive complexity was reduced in `result-utils.ts`, `stats-utils.ts`, and `setup-generator.ts` by extracting nested conditional logic into helper functions and flattening branching chains. Sort calls in test files were updated to use a `localeCompare`-based comparator where required by SonarCloud.

---

### Major: modernization and correctness fixes

- `bgg-import-utils.ts`: redundant `undefined` removed from function signatures
- `collection-utils.ts`: `.sort()` replaced with `.toSorted()` for non-mutating sort behavior
- `browser-entry.ts`: top-level `await` replaced with an explicit async wrapper
- `setup-generator.ts`: related parameters grouped into typed objects to reduce parameter count
- `setup-generator.test.ts`: nested template literals replaced with string concatenation

---

### Minor: language-modernization sweep

A broad pass across many files replaced legacy patterns with modern equivalents: type assertions removed where types were already inferred; `||` replaced with `??` for nullish checks; `Object.hasOwn()`, `structuredClone()`, `Set` membership checks, `String#replaceAll()`, `String.raw`, `globalThis`, `TypeError`, and `export … from` re-export syntax introduced where applicable; union type redundancies removed.

---

### Code duplication reduction (Epic 94)

Thirteen duplicate test cases were removed by extracting shared test helpers into a new `src/app/test-utils.ts` module. The helpers `createMemoryStorage`, `minimalIndexes`, `createAllOwnedState`, and `createSampleSnapshot` were pulled from 15 test files that previously defined them inline. The `mergeOwnedSets` test suite was consolidated from `myludo-import-utils.test.ts` and `bgg-import-utils.test.ts` into the canonical `collection-utils.test.ts`. Verbatim duplicate test blocks were also removed from `setup-rules.test.ts`, `BrowseTab.test.ts`, and `theme-utils.test.ts`. The unit test count decreased from 480 to 467 as a direct result of removing duplicate coverage. No production behaviour was changed.

### SonarCloud Code Quality Remediation — Round 2 (Epic 96)

A second remediation pass resolved 18 additional SonarCloud Maintainability findings introduced by the code shipped in Epics 29–95.

**Redundant type assertions removed (9 occurrences):** Unnecessary `as Type` casts that did not change the inferred type were removed from `game-data-normalizer.ts`, `new-game-utils.ts`, `result-utils.ts`, `setup-generator.ts` (4 occurrences), and `setup-validator.ts` (2 occurrences). Where TypeScript required narrowing after removing a cast, a proper type guard was added instead.

**Unsafe object-to-string conversions fixed (5 occurrences):** Five locations where an `unknown`-typed value could have produced `[object Object]` in a string context were corrected. In `state-sanitizer.ts` (2 occurrences), the `String(r.id ?? 'unknown')` pattern was replaced with an explicit `typeof r.id === 'string' ? r.id : 'unknown'` guard. Similar narrowing was applied to `result-utils.ts`, `history-utils.ts`, and `localization-utils.ts`.

**Negated conditions simplified (2 occurrences):** Two `if (!condition)` branches in `result-utils.ts` (lines 88 and 274) were inverted so the positive case leads, improving readability per the Sonar rule.

**Parameter count reduced (1 occurrence):** `buildCategorySelection` in `setup-category-selector.ts` exceeded the 7-parameter limit. The `random` and `forcedPicks` parameters were folded into the existing `opts` object, reducing the signature to 6 parameters. All call sites updated accordingly.

### Large files split into focused single-responsibility modules

Ten source files were identified as violating the 300-line single-responsibility guideline. Five were critically over-limit (600–1 030 lines each). The refactoring extracted cohesive concerns into new dedicated modules:

**`setup-generator.ts`** (was ~1 030 lines) — five concerns extracted into:
- `setup-pool-builder.ts` — pool construction (`buildOwnedPools`)
- `setup-freshness.ts` — freshness ranking and item selection
- `setup-scheme-modifiers.ts` — scheme modifier application
- `setup-validator.ts` — legality validation public API
- `setup-hero-selector.ts` — hero selection with team and name constraints
- `setup-category-selector.ts` — villain and henchman selection

**`state-store.ts`** (was ~670 lines) — three concerns extracted into:
- `state-sanitizer.ts` — all sanitization functions
- `state-io.ts` — load, save, update, and hydrate operations

**Component files split:**
- `HistoryTab.svelte` (was ~640 lines) → `GameResultEditor.svelte` + `HistoryInsightsDashboard.svelte`
- `NewGameTab.svelte` (was ~590 lines) → `ForcedPicksPanel.svelte` + `ActiveSetFilterPanel.svelte` + `SetupResultCard.svelte`
- `BrowseTab.svelte` (was ~490 lines) → `BrowseHelpDisclosure.svelte` + `BrowseHeroSection.svelte` + `AboutPanel.svelte`
- `CollectionTab.svelte` (was ~395 lines) → `CollectionSetsView.svelte`

Each new module ships with a co-located test file. All existing tests continue to pass and all original public API surfaces are preserved — imports from consuming files were updated where needed.
